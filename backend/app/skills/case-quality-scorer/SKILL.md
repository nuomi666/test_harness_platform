# 用例质量评审 Skill

## 概述
本 Skill 对 9 列标准测试用例做**量化质量评审**，回答两个问题：
1. **这条用例该不该留**（删留建议：保留 / 待改进 / 建议删除——删除不直接生效，走人工确认闸门）；
2. **这条用例能不能进 UI 自动化**（可自动化性标签 + 前置 fixture 模式归纳）。

与 `req-review`（需求评审）是两个完全不同的 Skill：req-review 评的是**需求**，本 Skill 评的是**用例产物**。

## 双引擎结构

### 引擎 A：代码硬指标（必跑，零模型调用，可复算）
| 编号 | 指标 | 严重度 | 说明 |
|---|---|---|---|
| A1 | 9 列完整性 + 用例名非空 | high | 缺列说明生成/解析链路出了问题 |
| A2 | 步骤-预期 [n] 编号配对 | medium | 步骤有 [2] 预期没 [2] ⇒ 断言映射断裂 |
| A3 | 备注列编号引用有效性 | medium | 引用的 R/S/F 编号必须真实存在于规则文件（对照规则全文，精确取，不走语义召回） |
| A4 | 同批用例名重复 | high | 归并/删除按名定位，重名 = 歧义 |
| A5 | 与历史用例语义重复 | low | 向量 L2 距离低于阈值 ⇒ 仅提示，不参与删留（阈值 `CASE_SCORE_DUP_DISTANCE`） |
| A6 | 枚举合法性 | medium | 标签 ∈ {功能测试,异常测试,UI校验,边界测试,状态测试}；等级 ∈ {P0,P1,P2}；编辑模式 ∈ {STEP,TABLE,FREE} |
| A7 | 模型自语泄漏 / 模糊预期 | high / medium | 正则黑名单；命中前置/步骤/预期列 |

扣分：high=30，medium=10，low=5（单条封顶 100）。

### 引擎 B：LLM rubric 锚定打分（可跳过）
| 维度 | 权重 | 锚点摘要（完整锚点见 references/scoring_rubric.md） |
|---|---|---|
| B1 步骤可执行性 | 25% | 5=每步单一动作控件指称唯一；3=有合并步可机械拆分；1=依赖人类上下文 |
| B2 预期可验证性 | 30% | 5=全是值/状态断言；3=含弱断言；1=含"根据实际展示"类不可断言表述 |
| B3 业务正确性 | 25% | **依据规则全文逐条比对**：矛盾=1（须写明与哪条规则矛盾）；未覆盖=3（标"待人工确认"）；一致=5 |
| B4 覆盖价值 | 20% | 5=覆盖 P0/P1 规则不冗余；3=部分冗余；1=重复覆盖低价值场景 |

总分 = Σ(维度分/5 × 权重 × 100) − 引擎 A 扣分；引擎 B 跳过时总分 = 100 − 引擎 A 扣分。

## 防打分漂移硬约束
1. **rubric 写死在本文件与 references/scoring_rubric.md**，每次评审用同一份锚点（改盘需重启生效）；
2. 跨批次重评时附带历史分数，变化 >15 分标「分数漂移」待人工看（阈值 `CASE_SCORE_DRIFT_DELTA`）；
3. 模型输出**强制 JSON**（每维 1~5 整数 + 一句话理由），解析失败重试一次，再失败该片标「评审失败」——
   失败片的用例只有引擎 A 分数，在报告中明确标注，**不静默、不猜分**；
4. 模型返回的用例名必须与输入**逐字一致**，对不上的条目直接丢弃并记告警（防模型改写名称后张冠李戴）。

## 分档与删留（人工闸门）
| 总分 | 处置 |
|---|---|
| ≥ 85 | ✅ 保留，进入自动化候选 |
| 60 ~ 84 | ⚠️ 待改进（报告列出具体维度短板） |
| < 60 或命中 high 硬伤 | ❌ 建议删除/重写 |

**删除建议不直接生效**：人工确认后，差评用例从**新版本基线**中移除（旧版本仍可追溯，不物理删），
删除原因记录于评分旁挂文件 `metadata/modules/{module}_case_scores.json`。

## 可自动化性标签（供 UI 自动化准入使用）
- `可直接自动化`：B1≥4 且 B2≥4 且前置可用接口构造
- `弱断言可自动化`：含布局类/观察型弱断言
- `需改造后自动化`：模糊预期待补 / 前置需组合 fixture
- `人工保留`：视觉美观、感官判断类

准入规则：可进入 UI 自动化 ⇔ 总分 ≥ 阈值 且 可自动化性 ∈ {可直接自动化, 弱断言可自动化}。

## 输入变量
- cases: 结构化用例列表（`metadata_manager.parse_markdown_cases` 的输出）
- module / page: 业务归属（A3/A5 与规则全文注入的定位锚点；为空则 A3/A5 跳过、B3 按锚点降级）
- use_engine_b: 是否启用引擎 B（False=纯代码体检，零模型调用）
- rules_full: 模块规则全文（B3 依据；空则由 Skill 按 (module,page) 精确自取）

## 输出
- 逐条结果：总分 / 维度分 / 引擎A硬伤清单（含原文摘录）/ 可自动化性 / fixture 模式 / 删留建议 / 理由
- 汇总：三档计数 / 均分 / 硬伤统计 / 失败片 / 分数漂移数
- Markdown 评审报告：落 `report/{slug}-case_review_report.md`（报告类资产统一放 report/ 目录）

## 环境变量
| 变量 | 默认 | 说明 |
|---|---|---|
| CASE_SCORE_SEGMENT_SIZE | 12 | 引擎 B 每片用例数 |
| CASE_SCORE_KEEP_THRESHOLD | 85 | 保留阈值 |
| CASE_SCORE_DELETE_THRESHOLD | 60 | 建议删除阈值 |
| CASE_SCORE_DRIFT_DELTA | 15 | 分数漂移告警阈值 |
| CASE_SCORE_DUP_DISTANCE | 0.6 | A5 语义重复 L2 距离阈值（仅提示） |
