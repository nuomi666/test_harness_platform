## 工作流
1. 加载通用需求评审Checklist
2. 逐条对照需求，检查是否存在遗漏或不明确的地方
3. 针对每个问题，给出具体的改进建议
4. 按严重程度对问题进行分类
5. 输出结构化的问题清单

## 评审Checklist
### 完整性检查
- [ ] 需求是否明确描述了所有功能场景
- [ ] 是否包含正常流程和异常流程
- [ ] 是否明确了输入、处理和输出的所有细节
- [ ] 是否明确了边界条件和限制
- [ ] 是否包含非功能需求（性能、安全、兼容性）

### 一致性检查
- [ ] 需求描述是否前后一致，没有矛盾
- [ ] 是否与现有系统的业务规则一致
- [ ] 术语是否统一，没有歧义

### 可测试性检查
- [ ] 需求是否可量化、可验证
- [ ] 是否明确了预期结果
- [ ] 是否提供了测试数据或示例

### 合理性检查
- [ ] 需求是否符合用户的实际使用场景
- [ ] 技术实现是否可行
- [ ] 是否存在逻辑漏洞

## 输出格式
### 一、问题清单
| 序号 | 问题描述 | 严重程度 | 改进建议 |
|------|----------|----------|----------|
| 1 | 未明确验证码的有效时长 | 高 | 建议明确验证码有效期为5分钟 |
| 2 | 未说明验证码错误多少次后锁定账号 | 中 | 建议明确验证码错误3次后刷新验证码 |
| 3 | 未提及验证码的大小写是否敏感 | 低 | 建议明确验证码不区分大小写 |

### 二、严重程度说明
- 高：影响核心功能，必须修改
- 中：影响用户体验，建议修改
- 低：不影响功能，可选择性修改

### 二、评审结论
需求整体清晰，但存在部分细节缺失，建议补充上述问题后通过评审。
