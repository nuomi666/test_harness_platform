# 卡BIN原数据文件历史页面（orig_file_page_rules）

> 本规则采用「编号条目」写法：第 4 章核心业务规则（R 编号）、第 5 章状态流转（S 编号）是生成用例的**必覆盖条目源**，每一条都必须产出对应用例（条数不低于该条「必生成数」），并在输出末尾的「编号覆盖自检表」中逐条打勾核对。第 1~3 章是给模型理解页面 UI 的背景信息，不承载必覆盖项。
>
> ⚠️ 本页面文件状态共 **8 种**：上传中（XX/XXX）、上传失败、解析中、解析失败、解析成功、需人工处理、已处理、已取消。各状态的可见操作**严格按下表**生成，不得漏配、错配（R9 + S 表）。

## 1. 页面定位与数据流向

- **定位**：卡BIN原始数据进入系统的入口页面，管理外部来源的原始 BIN 文件，支持上传/自动拉取、解析状态追踪、原文件下载；解析成功的数据同步至卡BIN池。
- **数据来源**：
  - 手动上传：通过本页面「上传文件弹窗」上传。
  - SFTP自动拉取：系统后台按规则自动拉取，无需人工操作。
- **下游**：
  - 「卡BIN池管理」——解析成功后数据同步入池（数据来源标记「文件导入」）。
  - 「冲突裁决 / 裁决详情」——解析后检测到与池中手工创建数据冲突时，进入冲突裁决页面处理。
- **本页面边界**：仅负责文件上传/拉取、解析、状态追踪、原文件下载与冲突检测；不涉及 BIN 数据日常维护（归下游池管理），不涉及冲突的具体决策（归冲突裁决页面）。

- **固定列**：文件名 | 文件大小 | 获取时间 | 获取方式 | 解析状态 | BIN记录数 | 操作
- **状态枚举（8 种）与可见操作（严格按此表生成）：**

| 状态 | 说明 | 可见操作 |
|---|---|---|
| 上传中（XX/XXX） | 文件上传至 KlondPay，因文件较大上传需一段时间；支持后台静默上传 | 取消上传 |
| 上传失败 | 文件上传至 KlondPay 失败（网络波动、存储异常等） | 重新上传 / 删除 |
| 解析中 | 文件上传成功，系统正在进行格式校验、去重、冲突检测等操作 | 无 |
| 解析失败 | 文件解析过程中发生错误（格式异常、数据损坏等），可重新解析或删除 | 重新解析 / 删除 |
| 解析成功 | 文件解析完成，已通过格式校验和去重，待进入冲突判定 | 下载文件 |
| 需人工处理 ⚠️冲突 | 解析完成，但检测到与手动创建数据存在 BIN 范围冲突，需运营人工裁决 | 冲突裁决 |
| 已处理 | 数据已成功写入卡BIN池（自动入库 或 冲突裁决后入库），可参与版本生成 | 下载文件 / 裁决详情 |
| 已取消 | 运营主动放弃本次文件导入，文件不做任何数据处理（取消上传 和 取消导入） | 删除 / 裁决详情 |

- **「裁决详情」显示条件**：**已处理**与**已取消**状态下的「裁决详情」**仅当该文件有裁决处理时才显示**。
- **进度展示**：上传中状态值展示为「上传中（XX/XXX）」，XX=已上传成功文件数，XXX=总文件数。
- **默认排序**：按获取时间倒序。
- **失败原因**：上传失败/解析失败在对应状态上展示失败原因。

## 4. 核心业务规则（必覆盖条目，编号 R）

> 每条规则必须生成不低于「必生成数」的用例，并按「覆盖要求」列补齐各业务态（正向/异常/边界/状态）场景，缺一不可。

| 编号 | 规则 | 描述 | 等级 | 必生成数 | 覆盖要求 |
|---|---|---|---|---|---|
| R1 | 文件结构合法性校验 | 不通过则**直接解析失败**：①**定长约束**：文件总字节数必须是 251（单条记录长度）的整数倍；②**最小记录约束**：总记录数 = 文件大小 / 251，不得小于 3（至少 1 条文件头 + 1 条数据记录 + 1 条尾记录）；③**记录完整性**：所有记录均为定长 251 字节，无截断、无超长、无乱码；④**首尾记录规则**：文件头与尾记录不计入有效 BIN 记录数，有效数据记录数 = 总记录数 − 2 | P0 | 4 | 异常：非251整数倍→解析失败1条、总记录数<3→解析失败1条、乱码/截断→解析失败1条；边界：恰好3条记录（有效数据1条）解析通过1条 |
| R2 | 相邻记录合并规则 | 两条连续记录同时满足「**区间连续**：前一条 highBin + 1 = 后一条 lowBin」+「**属性一致**：PAN 长度、卡类型、国家代码、标志位、产品 ID 完全一致」时，解析后**自动合并为一条**；合并后扩展高值为后一条的 highBin，记录总数减 1 | P0 | 3 | 正向：区间连续且属性一致→合并为一条、区间范围正确1条；边界：区间连续但属性不一致→不合并1条；边界：属性一致但区间不连续→不合并1条 |
| R3 | BIN记录数口径 | 页面展示的「BIN 记录数」= **合并后的有效数据记录总数**，与文件实际有效数据量一致（**非源文件原始行数**） | P1 | 2 | 正向：BIN记录数与合并后有效数据量一致1条；边界：文件头/尾记录不计入1条 |
| R4 | 冲突检测规则 | 解析完成后自动检测解析出的 BIN 记录与卡BIN池**「手工创建」来源**记录是否存在 BIN 范围重叠。**无冲突**→所有新数据自动入库（池中 FirstData 旧数据全量替换），文件状态→「已处理」；**有冲突**→文件状态→「需人工处理」，等待人工裁决 | P0 | 3 | 正向：无冲突→自动入库、状态转「已处理」1条；异常：与手工创建记录重叠→状态转「需人工处理」、不直接入库1条；边界：与「文件导入」来源记录重叠→不判为冲突1条 |
| R5 | 解析结果一致性校验 | ①解析后单条记录的卡品牌、卡类型、国家、卡等级、各类标志位与源文件字段定义**一一对应**；②解析成功的数据自动同步至卡BIN池，**数据来源标记为「文件导入」**，字段内容与解析结果完全一致 | P0 | 2 | 正向：解析字段与源文件定义一一对应1条；正向：同步至池来源标记「文件导入」且字段一致1条 |
| R6 | 上传文件校验与文件替换 | ①上传时**不对文件格式（扩展名）作限制**；②**一次只能上传一个文件**；③未选择任何文件时点击「确定」提示先上传文件；④提交上传过程中「确定」按钮**置灰防重复提交**；⑤替换文件需**先删除**之前上传的文件，再重新上传 | P0 | 4 | 异常：未选文件点确定→提示先上传文件1条、提交中重复点击确定→不触发多次上传1条、一次选择多个文件→仅保留1个1条；正向：替换文件需先删除再上传1条 |
| R7 | 上传与获取方式 | 获取方式枚举：**手动上传**（本页面上传弹窗）与 **SFTP自动拉取**（系统后台按规则自动拉取，无需人工操作）；列表「获取方式」列按来源正确标识 | P1 | 2 | 正向：手动上传记录获取方式=手动上传1条；正向：SFTP自动拉取记录获取方式=SFTP自动拉取1条 |
| R8 | 上传中与静默上传 | 文件较大，上传需一段时间；**支持后台静默上传**（上传中离开/切换页面不中断，返回后状态与进度正确） | P2 | 1 | 正向：上传中切换页面再返回，上传不中断且状态/进度正确1条 |
| R9 | 状态-操作联动 | 8 种状态各展示对应的操作集（**严格按第 2.3 节表**）：上传中=取消上传；上传失败=重新上传/删除；解析中=无；解析失败=重新解析/删除；解析成功=下载文件；需人工处理=冲突裁决；已处理=下载文件/裁决详情；已取消=删除/裁决详情。**已处理、已取消的「裁决详情」仅当该文件有裁决处理时才显示** | P0 | 4 | 正向：上传中仅「取消上传」1条、解析中无任何操作1条、需人工处理仅「冲突裁决」1条；状态：已处理/已取消的「裁决详情」有裁决时显示、无裁决时不显示1条；异常：非对应状态的按钮不得出现 |
| R10 | 重新解析限制 | 若某个「解析失败」记录**之后（按获取时间）已存在「解析成功」的文件**，则该失败记录**不再提供「重新解析」**能力（按钮隐藏或置灰） | P0 | 2 | 异常：存在更晚的解析成功文件时→该失败记录无「重新解析」1条；正向：不存在更晚成功文件时「重新解析」可用1条 |
| R11 | 失败原因展示与异常反馈 | 上传失败/解析失败在对应状态上展示**失败原因**；上传失败保留弹窗并提示失败原因，可重新选择文件重试；点击「取消」或弹窗蒙层关闭弹窗，不提交上传、不保留已选文件状态 | P1 | 3 | 正向：解析失败展示失败原因1条；异常：上传失败保留弹窗+失败原因+可重新选择1条；正向：取消/蒙层关闭弹窗后不提交、已选文件不保留1条 |
