# 通用需求评审Checklist
## 完整性检查
- [ ] 需求是否明确描述了功能的输入、处理、输出
- [ ] 是否包含所有异常场景的处理规则
- [ ] 是否明确了性能、安全、兼容性等非功能需求
- [ ] 是否明确了边界条件和限制

## 一致性检查
- [ ] 需求描述是否前后一致，没有矛盾
- [ ] 是否与现有系统的业务规则一致
- [ ] 术语是否统一，没有歧义

## 可测试性检查
- [ ] 需求是否可量化、可验证
- [ ] 是否明确了预期结果
- [ ] 是否提供了测试数据或示例

## 合理性检查
- [ ] 需求是否符合用户的实际使用场景
- [ ] 技术实现是否可行
- [ ] 是否存在逻辑漏洞
